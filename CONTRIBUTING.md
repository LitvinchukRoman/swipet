# Contributing to Swipet

Stay small, stay green, stay reviewable.

## 1. Git flow

We use a lightweight GitHub flow on top of `develop` / `main`:

| Branch | Source of truth for | Merge rule |
| --- | --- | --- |
| `main` | production-ready, deployable | only fast-forward from `develop`, requires review |
| `develop` | active integration branch | all features go here first |
| `feature/<TASK-ID>-short-slug` | one logical change | squash-merge into `develop` |
| `bugfix/<short-desc>` | non-urgent fix | squash-merge into `develop` |
| `hotfix/<short-desc>` | critical prod fix | branched from `main`, merged into both `main` and `develop` |

Examples:

```
feature/AU-007-jwt-auth-filter
feature/AN-006-feed-haversine-query
bugfix/auth-refresh-rotation-409
hotfix/cors-prod-misconfig
```

## 2. Commits

Conventional Commits with the **task id**:

```
feat(AU-007): add JwtAuthFilter and SecurityConfig
fix(GEN-004):  permit OPTIONS on /api/* for CORS
docs:         tighten README quick-start
```

Allowed types: `feat | fix | refactor | docs | test | chore | perf | build | ci`.

## 3. Pull requests

- Base branch: `develop` (unless it's a hotfix → `main`).
- ≤ 400 changed lines. Bigger? Split it.
- At least **1 reviewer** before merge.
- All CI checks must be green (build + tests on backend, Jest on chat-service,
  Jest+RTL on frontend — once enabled).
- PR description template:
  - **What** — 1–2 sentences.
  - **Why** — link to task / ticket.
  - **Test plan** — how to verify locally (commands).
  - **Risks / follow-ups** — known unknowns.
- Don't disable failing tests. Either fix the test or open a follow-up
  ticket and skip with a clear `@Disabled("AU-013 follow-up")`.

## 4. Where to run tests

| Service | Command | Notes |
| --- | --- | --- |
| `backend/` | `./gradlew test` | unit + integration; Testcontainers spins up Postgres on demand. Requires Docker. |
| `backend/` | `./gradlew jacocoTestReport` | coverage HTML at `build/reports/jacoco/test/html/index.html` |
| `chat-service/` | `npm test` | Node `--test` (placeholder until Андрій lands real implementation) |
| `frontend/` | `npm test` | Jest + React Testing Library |
| repo root | `docker compose up --build` | end-to-end smoke; hit `https://localhost/api/v1/auth/...` |

## 5. Code style

- **Java**: stick to project conventions — Lombok for boilerplate, records
  for DTOs, `@Transactional` only on services, no business logic in
  controllers, no `RuntimeException("foo")` — throw `AppException` with a code.
- **JS/TS**: ES modules, no default exports for services, prefer named
  exports.
- **SQL migrations**: forward-only. Never edit a migration that's already
  been merged. Add a new `Vn__*.sql` instead.

## 6. Secrets

- Never commit `.env`, `*.key`, `*.crt`, real `JWT_SECRET`, real S3 creds.
- `git-secrets` / pre-commit hook recommended (TODO: wire in `INF-CI`).
- If a secret leaks: rotate it first, *then* fix the repo.

## 7. Definition of Done

A task is "done" (mergeable into `develop`) when:

1. Code compiles, no new linter warnings.
2. New / changed behavior is covered by tests.
3. All existing tests still pass.
4. Public API change → `docs/api/CONTRACT.md` updated.
5. New ENV var → `.env.example` + README updated.
6. Swagger renders the new endpoint (autogenerated from controller).
7. PR description has *what / why / test plan*.
